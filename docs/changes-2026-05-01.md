## Issue: placeholder-step6-gate-rloo-on-hard-correctness

- Hypothesis:
  RLOO should not run by default when the upstream SFT checkpoint is still at fluke-level hard correctness; gating RL on a minimum hard-retry signal will save time and keep the workflow focused on the real blocker.
- Change made:
  Added a pre-RLOO hard retry gate to the replication/default workflow:
  - script now evaluates the post-SFT checkpoint on `countdown-test-hard.jsonl` before RL
  - RLOO only starts if hard correct count clears the configured floor
  - default floor is `2` correct hard examples, overrideable with `LTR_RLOO_MIN_HARD_CORRECT`
  - emergency bypass is available via `LTR_RLOO_GATE_DISABLE=1`

  Updated the README, runbook, and status docs to make this gate part of the recommended default workflow.
